Week 97: Square remainders

Mathematical kernels

1. Square a whole number then remove complete bundles of m; the leftover depends only on the original remainder modulo m. The square map can send different inputs to the same output. For odd prime p, x squared and y squared have the same remainder iff x=y or x=p-y among 0,...,p-1. Proof: p divides (x-y)(x+y), so divides a factor; pairing nonzero inputs gives exactly (p-1)/2 nonzero square outputs and one zero input. Concrete grouping and sorting should precede this statement; do not print the discovery as a procedure.

2. Composite moduli reveal different collision structure, not a false universal two-root rule. Modulo 8: zero has inputs 0, 4; one has 1, 3, 5, 7; four has 2, 6. Modulo 9: zero has 0, 3, 6; one has 1, 8; four has 2, 7; seven has 4, 5. Modulo 15: one has 1, 4, 11, 14. Optional deeper continuation: among nonzero residues modulo an odd prime, square times square is square, square times nonsquare is nonsquare, nonsquare times nonsquare is square, via bijections. State limits carefully, exclude zero for that classification, and do not make universal claims from finite tables. This connects multiplicative prime structure to information loss and polynomial equations. Avoid repeating Week 4 multiplication portraits/cipher wheels or Week 33 Fermat necklace theorem.

Suggested emphasis by level: one coherent Grades 3–5 packet, no forced K–1/2–3 variants. Concrete entry requires equal bundles, square arrays, and supported multiplication; deeper route needs systematic coverage and elementary divisibility reasoning. Zero input and zero remainder must be visible participants. General prime proof can remain a facilitated later challenge; retain substantive composite comparisons and upper depth.

Materials

For each pair: 64 counters or square tiles, whiteboard, grouping circles/strips drawn on scrap paper, reusable input cards and output sorting labels. For larger squares use supplied arithmetic support or printed square arrays so multiplication/transcription does not displace mathematics. A square area is x times x, not perimeter. Before first use give an explicit worked visual from an input square via complete m-bundles to leftover/output, using a non-task instance. Explain why leftovers are being compared: to discover which outputs square inputs can produce and how much the leftover reveals about the input. Let pupils choose methods and organize catalogs; do not prescribe opposite pairing or a sequence of mechanical table entries. Keep counts practical; modulo 15 is a later arithmetic-supported continuation, not a requirement to build 196 counters. Leave exact problem choices and sequence to writer.
