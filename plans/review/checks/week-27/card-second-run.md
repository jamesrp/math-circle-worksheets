## The mathematics

Two sides rank each other; a pairing is stable when no circle and square in different pairs both prefer each other. A profile can have one stable pairing or several, and none may give everyone a first choice (K–1 P1–P2, 2–3 P2–P4). Deferred acceptance always ends, within n² requests, in a stable pairing, because askers move down their lists while receivers only trade up; the asking side matters, and a first-come rule fails (4–5 P2–P5). In a stable three-pair pairing at most three letters get their last choice (4–5 P6). A mathematician would enjoy it: Gale–Shapley with child-sized proofs, and inverse and impossibility problems in every band.

## Fix

1. **must**, all bands, guide p. 2: "Separate full-size table materials are required … They are not cut-out cards, work mats, or substitutes", and "Copy the exact profile for the selected problem". Nothing prints tokens, strips, links or markers, so a parent volunteer must build a kit and transcribe each case at the table (32 entries for 2–3 P4). Fix: a print-and-cut page with 25 mm circle tokens A–D, square tokens W–Z, sixteen asked-markers, and K–1 P3's eight strips each beside a reversed copy. Rewrite p. 2: read the printed strips in place; pair tokens on the table or draw lines on the page boards.
2. **should**, guide p. 2 launch: "A: X > Y; B: X > Y; X: A > B; Y: A > B" is K–1 P1's bottom case and 2–3 P1's top case, and the launch settles both pairings (math check, problem 3). Use A: Y > X; B: X > Y; X: A > B; Y: A > B: place AY/BX (X wants A, A doesn't), then AX/BY (A and Y block).
3. **should**, guide overview and p. 1: "Participation requires understanding why only the first is a blocking pair". Only an adult enforces the check, and context.md records a paper-only rule failing (prediction). Fix: four children each hold one letter's strip and answer for it; a pair blocks only if both say they would switch. Make this the K–1 entry on P1, not a gate.
4. **should**, 2–3 p. 2, P1: "join two letters that both want to change." In the bottom case both pairings stay, yet both circles want to change in AY/BX and both squares in AX/BY, inviting the one-sided error the guide lists (p. 16). Write "join a circle and a square that would both rather be together."
5. **should**, 2–3 p. 5 P4 and K–1 p. 7 P6: four boards for exactly four stable pairings of 24, two for exactly two profiles of 16, so the page answers "is that all?". Print six boards for P4; add a page of extra P6 workspace.
6. **should**, guide p. 6: "Here is a full audit … the checker records all blockers", yet AX/BY/CZ lists only BX (BZ, CX, CY also block) and AZ/BY/CX only AY (BZ, CY also). An adult may reject a right blocker; should, not must, because the answer asked for is right. Write "the table shows one blocker; a child may find another."
7. **should**, guide p. 13: "Exact expected answer: 16 requests". Any bound from 13 up with a reason is right (math check, problem 2). Retitle "A sufficient answer" and add the 13 argument.
8. **should**, guide pp. 10–13: 4–5 runs the rules on one profile before P4–P5 ask about every run. Suggest also running P1's profiles, whose answers children know: the bottom gives AY/BZ/CX from either side; the top gives each asking side its first choices.
9. **could**, 4–5 p. 2: put the rules before "Use these rules"; the 8.5 × 2 cm record boxes fit eight requests only in shorthand.
10. **could**, guide p. 12: the P3 example fails only if A asks before B; use the math check's order-proof profile.
11. **could**, guide pp. 1, 17: cut the build residue ("library label", "Fidelity", "Checks packaged"); number the route note 18.
12. **could**, K–1 P4's top case is a P6 answer; change one strip.

## App fit

B, size M, confirmed, but flag blocking pairs on submit, not live. The child drags links and claims "stable"; a wrong claim gets one blocking pair. Find-all ends when the child declares "that's all", with no counter. Inverse puzzles click best: fill strips so one, both or exactly two pairings stay (K–1 P4–P6, 2–3 P5); flip one strip to repair (K–1 P3); design lists where the asking sides disagree or the first-come rule fails (4–5 P2–P3); three last choices (4–5 P6). Certificates for "can't": a blocker away from the blank strip (K–1 P4), two blockers with disjoint letters (K–1 P3). Pitfalls: watching the asking run is predicting; live flags turn search into wiggling; no marriage framing.
