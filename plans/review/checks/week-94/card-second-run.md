## The mathematics

An instrument with an unknown offset reports length plus b. Reports fix differences of lengths but not lengths, since (x + t, b − t) reads the same, so a known reference is needed; three references let one wrong report be repaired (2–3 P2–P7). For y = a + bx, two references fix the rule and one never does; a third can refute it, and with no model promised no tests force an untested value (4–5 P3–P5). With display errors up to 1, references D apart leave the stretch in an interval no wider than 4/D, so references 1 and 10 are best and a repeated reference never pins it (P6–P7). A mathematician would enjoy it. K–1 reaches only the first step: on a ruler starting at 2, length is spaces, not the end label.

## App fit

Not in themes.md. I propose Fit B, size S, as a group in Ruler strips (Week 51), whose board is strips on a ruler.

- **Finite machine** (4–5 P1–P2): the child drops a known strip, or builds a length 1–12, into the machine; the app lays the report bar. The machine is slippery, as in Slippery secrets, keeping any of the 21 rules that fit. Name it within a budget; a loss ends with two rules that fit every report. One request wins only with length 7 or more; below that, two rules share a report (length 6: 1 copy + 6 and 2 copies + 0 give 12).
- **Shared offset** (2–3 P2–P3): build P and Q bars for reports 7 and 10; That's all, no slot per pair.
- **Repair** (2–3 P6, 4–5 P4): tap the wrong report and drag it; every repair, judged by That's all.
- **Bands** (4–5 P6): drag each true report inside its band and pin the smallest and largest stretch.

Pitfalls: no typed reports for given inputs, which is prediction; no count of rules left; a half-unit grid for P4's 11½. P5 and P7 stay on paper.
